# 운영원칙

## 기준 자료

- 회사의 `00_ 캠스 MSDS` 폴더를 최신 PDF 원본 기준으로 사용합니다.
- 등록대장 엑셀은 신규·변경 비교와 문제 분석을 위한 참고 자료입니다.
- 엑셀 전체를 `data/msds.local.json` 위에 통째로 덮어쓰지 않습니다.
- 등록대장의 날짜는 사이트 날짜 필드에 직접 덮어쓰지 않습니다. 최초 작성일과 최종 개정일은 PDF 원문만 기준으로 합니다.
- 사이트에는 필요한 제품만 선택적으로 갱신하고 PDF 원문과 다시 대조합니다.

## 업데이트 순서

1. 기존 PDF와 local JSON을 백업합니다.
2. 원본과 사이트 PDF의 경로, 파일명, 해시를 비교합니다.
3. 신규·변경 PDF만 반영합니다.
4. 등록대장 업데이트 이력은 참고값으로 읽습니다.
5. 대상 제품의 개정일, CAS, 함유량, GHS, H/P 문구만 선택 갱신합니다.
6. 인벤토리와 링크 검사를 다시 실행합니다.
7. 공개용 JSON을 생성합니다.
8. 실제 화면에서 검색과 PDF 미리보기를 확인합니다.

## 중복 처리

- SHA-256이 같은 완전 중복 PDF는 대표본 하나만 남길 수 있습니다.
- 삭제 전 반드시 대상 PDF와 local 데이터를 별도 백업합니다.
- 공급업체별 정식 폴더와 정상 파일명을 우선 대표본으로 선택합니다.
- 대표본 경로로 제품과 override 연결을 함께 바꿉니다.
- 제품명이나 성분이 비슷한 `내용 유사 후보`는 자동 삭제하지 않습니다.
- 동명 파일은 내용이 같으면 하나로 정리할 수 있고, 내용이 다르면 별도 버전으로 유지합니다.

## 표시 문구

- 현장 화면에서 일반명으로 확인되는 영문 물질명은 한글 대표명으로 표시합니다.
- 브랜드명, 모델명, 고유 제품코드는 영문을 유지할 수 있습니다.
- 검증되지 않은 긴 중합체명이나 IUPAC명은 억지로 번역하지 않습니다.
- 오타를 고치되 CAS No.와 함유량을 바꾸는 수정은 반드시 원문 근거가 있어야 합니다.
- MSDS 요약은 편의를 위한 것이며 법적 근거자료는 원본 PDF입니다.

## GitHub 관리

- GitHub Pages에 필요한 `data/msds.public.json`, `data/msds-overrides.public.json`, `pdf/` 대표 PDF는 저장소에서 관리합니다.
- 원본 엑셀, `data/msds.local.json`, `data/msds-overrides.local.json`, `data/backups/`, `reports/*.local.*`는 GitHub에 올리지 않습니다.
- 거래처 공문, 별지, 내부 검토자료는 MSDS PDF 폴더에 넣지 않습니다.

## 안전장치

- 변경 전 dry-run 또는 비교 리포트를 먼저 확인합니다.
- 경로 밖 파일은 삭제하지 않습니다.
- 구버전 삭제와 중복 정리는 백업이 성공한 뒤에만 실행합니다.
- 공개 데이터 생성 후 제품 수와 PDF 수, 누락 링크, 중복 수를 확인합니다.
