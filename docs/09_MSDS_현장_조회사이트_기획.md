# 09. MSDS 현장 조회 사이트 기획

현재는 초안이며 추후 수정 가능합니다.

## 문서 목적

이 문서는 현장 작업자가 QR코드를 통해 접속하여 MSDS 정보를 빠르게 확인할 수 있는 조회 전용 사이트의 방향을 정리하기 위한 초안입니다.

현재 단계에서는 실제 웹사이트 코드, 실제 엑셀 변환, 실제 PDF 파일 연결, 실제 회사 자료 저장을 하지 않습니다.

이 문서는 나중에 실제 개발을 시작할 때 화면, 데이터, 검색 기능, PDF 연결 방식을 헷갈리지 않도록 미리 정리하는 용도입니다.

## 핵심 컨셉

MSDS 현장 조회 사이트는 복잡한 관리자용 MSDS 관리 시스템이 아닙니다.

현장 작업자가 종이 MSDS 파일을 찾지 않고, 현장에 부착된 QR코드를 스캔해서 필요한 물질 정보를 빠르게 확인하는 정보제공용 사이트입니다.

따라서 첫 화면은 단순해야 하며, 검색창이 가장 중요합니다.

## 사용 시나리오

1. 현장에 화학제품이나 소모품이 있습니다.
2. 작업자가 해당 물질의 MSDS 정보가 필요하다고 판단합니다.
3. 기존 종이 MSDS 파일을 찾는 대신 현장 QR코드를 스캔합니다.
4. MSDS 조회 사이트로 접속됩니다.
5. 첫 화면의 큰 검색창에 일부 단어를 입력합니다.
6. 정확한 제품명을 몰라도 관련 제품 목록이 표시됩니다.
7. 원하는 제품을 선택합니다.
8. 제품의 핵심 MSDS 정보를 확인합니다.
9. 필요하면 연결된 PDF MSDS를 다운로드보다 미리보기 방식으로 확인합니다.

예시:

```text
검색어: 이형
결과: 이형제 관련 제품 여러 개 표시

검색어: 2차이형제
결과: 2차이형제 제품 중심으로 좁혀짐
```

## 사이트 목적

- 현장 작업자가 MSDS 정보를 빠르게 확인할 수 있게 합니다.
- 모바일과 PC에서 모두 사용할 수 있게 합니다.
- QR코드 접속에 적합한 단순한 화면을 제공합니다.
- 로그인 없이 누구나 조회할 수 있게 합니다.
- 등록, 수정, 검토가 아니라 정보제공과 조회에 집중합니다.
- 종이 MSDS 파일을 대체하거나 보조하는 현장 검색 시스템으로 사용합니다.

## 현재 단계에서 하지 않는 일

현재 단계에서는 아래 작업을 하지 않습니다.

- 실제 웹사이트 코드 작성
- 실제 엑셀 파일 변환
- 실제 회사 MSDS 자료 저장
- 실제 PDF 파일 업로드 또는 연결
- 로그인 기능 구현
- 관리자 등록, 수정, 검토 화면 구현
- 외부 공개용 서버 설정
- 실제 데이터베이스 생성

## 데이터 기준

나중에 실제 개발을 할 때 사용할 데이터 기준은 아래와 같이 생각합니다.

| 구분 | 기준 |
|---|---|
| 엑셀 파일명 | `MSDS_통합대장_누적3.xlsx` |
| 주요 시트 | `통합종합_보기용` |
| 변환 결과 | 검색용 JSON 데이터 |
| PDF 저장 위치 | `/pdf/` 폴더 |
| PDF 연결 기준 | 엑셀의 `파일명` 컬럼과 PDF 파일명이 일치할 때 자동 연결 |

엑셀 데이터는 나중에 검색용 JSON으로 변환합니다.

이때 제품 기본정보와 성분정보를 분리해서 구조화합니다.

```text
제품 기본정보 1개
└─ 성분정보 여러 개
```

## 데이터 구조 방향

나중에 JSON 데이터로 만들 때는 아래처럼 구분합니다.

### 제품 기본정보

- 제품 고유 ID
- 제품명
- 캠스 ERP 품명
- MSDS번호
- 파일명
- PDF 경로
- 용도분류
- 권고용도 또는 사용용도
- 제조사 또는 공급업체
- 정보제공 및 긴급연락처
- 주요 유해성 분류
- 개정일
- 위험물 구분
- PPE 요약
- GHS 그림문자
- 검색용 통합 문자열

### 성분정보

- 연결되는 제품 고유 ID
- 화학물질명
- CAS No.
- 함유량(%)
- 관리대상 유해물질 여부
- 작업환경측정 대상 여부
- 특수건강진단 대상 여부

## 화면에 표시하지 않을 항목

아래 항목은 현장 정보제공용 화면에는 표시하지 않습니다.

- 업데이트 구분
- 성분별 법적대상구분
- 법적검토상태

다만 엑셀 원본에 해당 컬럼이 있어도 오류가 나지 않게 처리해야 합니다.

또한 나중에 관리자 화면에서 다시 사용할 수 있도록 원본 데이터 구조는 훼손하지 않습니다.

## 검색 기능 방향

검색은 정확한 제품명을 몰라도 결과가 나오는 방식으로 만듭니다.

### 검색 대상

검색 대상은 아래 항목을 중심으로 합니다.

- 제품명
- 캠스 ERP 품명
- MSDS번호
- 파일명
- 용도분류
- 제조사 또는 공급업체
- 화학물질명
- CAS No.

### 검색어 정규화

검색 전에는 사용자 입력값과 데이터 값을 모두 단순하게 정리합니다.

정규화란 같은 뜻인데 모양이 조금 다른 글자를 검색하기 쉽게 맞추는 작업입니다.

예를 들어 `2차이형제(S6) 2024.pdf`라는 파일명이 있을 때, 사용자가 `2차이형`, `S6`, `이형`, `2`만 입력해도 찾을 수 있게 만드는 것입니다.

정규화 규칙:

- 공백 제거
- 괄호 제거
- 하이픈 제거
- 언더바 제거
- 슬래시 제거
- `.pdf` 확장자 제거
- 영문 대소문자 구분하지 않음

### 검색 예시

| 데이터 예시 | 사용자가 입력해도 찾을 수 있는 검색어 |
|---|---|
| 제품명: `2차이형제 (S6)` | `2`, `2차`, `이형`, `2차이형`, `S6` |
| 파일명: `2차이형제(S6) 2024.pdf` | `2차이형제`, `S6`, `2024`, `이형제` |

검색어가 짧으면 관련 제품을 넓게 보여주고, 검색어가 길어질수록 결과가 자연스럽게 줄어들게 합니다.

## 메인 검색 화면

메인 화면은 현장 작업자가 QR코드로 접속했을 때 바로 검색할 수 있어야 합니다.

### 화면 구성

- 상단에 큰 검색창을 둡니다.
- 검색창 아래에 결과 카드를 표시합니다.
- 모바일 화면에서 한 손으로 보기 쉽게 글자와 버튼을 크게 둡니다.
- 불필요한 관리용 정보는 보이지 않게 합니다.

### 검색 결과 카드 표시 항목

검색 결과에는 너무 많은 정보를 보여주지 않습니다.

현장에서 바로 판단할 수 있는 핵심 정보만 표시합니다.

- 제품명
- 캠스 ERP 품명
- 용도분류
- 제조사 또는 공급업체
- 주요 유해성 분류
- 위험물 구분
- PPE 요약
- 개정일
- PDF 미리보기 버튼

## 상세 화면

제품을 클릭하면 상세 화면으로 이동하거나 상세 모달을 표시합니다.

상세 화면은 검색 결과보다 더 많은 정보를 보여주되, 현장 확인에 필요한 내용 중심으로 구성합니다.

### 상세 표시 항목

- 제품명
- 캠스 ERP 품명
- MSDS번호
- 파일명
- 용도분류
- 권고용도 또는 사용용도
- 제조사 또는 공급업체
- 정보제공 및 긴급연락처
- 주요 유해성 분류
- 개정일
- 위험물 구분
- PPE 요약
- GHS 그림문자
- 성분정보 목록
- PDF 미리보기

### 성분정보 목록 표시 항목

- 화학물질명
- CAS No.
- 함유량(%)
- 관리대상 유해물질 여부
- 작업환경측정 대상 여부
- 특수건강진단 대상 여부

## PDF 미리보기 방향

PDF는 다운로드보다 미리보기를 기본으로 합니다.

### 기본 원칙

- 제품 상세 화면에서 PDF를 바로 볼 수 있게 합니다.
- iframe 또는 PDF viewer 방식으로 표시합니다.
- 다운로드 버튼은 기본적으로 숨깁니다.
- 나중에 설정값으로 다운로드 버튼 표시 여부를 바꿀 수 있게 합니다.
- PDF 경로는 `/pdf/파일명` 형태로 연결합니다.
- 엑셀의 `파일명` 컬럼과 PDF 파일명이 일치하면 자동 연결합니다.

예시:

```text
엑셀 파일명 컬럼: 2차이형제(S6) 2024.pdf
PDF 경로: /pdf/2차이형제(S6) 2024.pdf
```

## 추천 폴더 구조

나중에 실제 정적 웹사이트를 만들 때의 권장 구조는 아래와 같습니다.

```text
msds-site
├─ index.html
├─ detail.html
├─ data
│  └─ msds-index.json
├─ pdf
│  └─ MSDS PDF 파일들
├─ scripts
│  └─ 엑셀을 JSON으로 변환하는 스크립트
└─ admin
   └─ 추후 관리자 기능용 폴더
```

처음에는 정적 웹사이트 방식으로 시작합니다.

즉, 서버와 데이터베이스를 바로 만들지 않고, 엑셀을 JSON으로 변환한 뒤 웹페이지가 그 JSON을 읽어 검색하는 방식입니다.

## 향후 확장 방향

처음에는 조회 전용으로 시작하되, 나중에 아래 기능을 추가할 수 있게 폴더와 데이터 구조를 분리합니다.

- 관리자용 제품 등록 화면
- 관리자용 제품 수정 화면
- 엑셀 업로드 기능
- PDF 업로드 기능
- 법적 검토 상태 관리
- 사용자 권한 관리
- 로그인 기능
- 변경 이력 관리
- 백업 기능
- 서버 이전 절차

## 1차 구현 전 확인할 사항

실제 개발 전에 아래 내용을 정해야 합니다.

- MSDS 사이트를 기존 CAMS EHS 포털 안에 넣을지, 별도 정적 사이트로 둘지
- QR코드가 접속할 첫 주소
- PDF 파일명과 엑셀 `파일명` 컬럼의 일치 기준
- 검색 결과에 너무 많이 노출되면 안 되는 정보가 있는지
- 현장 공개 범위
- 내부망 전용인지 외부 접속도 가능한지
- 다운로드 버튼을 계속 숨길지, 관리자 설정으로만 열지

## 최종 목표

현장 작업자가 QR코드를 찍고 사이트에 들어와서, 정확한 제품명을 몰라도 일부 단어만 검색해 MSDS 핵심정보와 PDF를 빠르게 확인할 수 있는 현장 정보제공용 MSDS 조회 사이트를 만드는 것이 최종 목표입니다.

현재는 이 목표를 실제 구현하지 않고, 나중에 안정적으로 만들 수 있도록 요구사항과 구조를 문서로 정리하는 단계입니다.
