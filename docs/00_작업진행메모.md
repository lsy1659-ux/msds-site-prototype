- 실제 웹사이트 코드, 실제 엑셀 변환, 실제 PDF 연결은 아직 만들지 않는 것으로 구분했습니다.

## 3. 다음에 해야 할 작업

다음 작업 후보는 아래와 같습니다.

- 월간환경관리의 실제 화면 초안을 더 구체화합니다.
- `2026년 04월 환경데이터 정리` 샘플 프로젝트 구조를 문서로 더 자세히 정리합니다.
- 12개 항목별로 필요한 원천자료와 산출물 관계를 표로 정리합니다.
- 각 항목별 입력값, 업로드 파일, 검증 기준을 정리합니다.
- 실제 자동화에 들어가기 전에 샘플 파일명 규칙을 정합니다.
- 나중에 웹 프로그램을 만들 때 사용할 DB 후보 구조를 문서로만 설계합니다.
- 엑셀 자동화 우선순위를 정합니다.
- MSDS 현장 조회 사이트를 기존 CAMS EHS 포털 안에 둘지, 별도 정적 사이트로 둘지 결정합니다.
- MSDS 조회 사이트의 샘플 데이터 구조를 실제 자료가 아닌 가상 데이터 기준으로 설계합니다.
- MSDS 조회용 JSON 구조와 엑셀 컬럼 매핑표를 문서로 정리합니다.
- PDF 파일명 규칙과 QR코드 접속 주소 기준을 정합니다.

## 4. 초보자가 기억해야 할 주의사항

- 지금은 설계 단계입니다. 아직 실제 프로그램을 만든 것이 아닙니다.
- `docs` 폴더는 설명서와 설계 문서를 모아두는 곳입니다.
- `data` 폴더는 나중에 파일을 어디에 둘지 미리 정리한 구조입니다.
- 실제 회사 자료나 실제 엑셀 파일은 아직 넣지 않습니다.
- 원본 파일은 직접 수정하지 않는 것이 원칙입니다.
- 자동화 작업은 원본이 아니라 복사본 또는 별도 가공 파일로 진행해야 합니다.
- KNK ERP 자료는 최종 결과물이 아니라 일부 항목을 만들기 위한 원천자료입니다.
- 1~12번 항목별 정리 파일은 최종 종합파일 전 단계의 중간 산출물입니다.
- 최종 통합 결과물은 DB가 아니라 출력 양식 또는 검증 비교용 파일입니다.
- 기능을 한 번에 다 만들지 말고, 작은 단위로 하나씩 추가해야 합니다.
- MSDS 조회 사이트도 현재는 기획 단계이며, 실제 회사 MSDS 엑셀이나 PDF를 아직 넣지 않습니다.
- 현장 정보제공용 화면에는 업데이트 구분, 성분별 법적대상구분, 법적검토상태 같은 관리용 항목을 표시하지 않습니다.
- 다만 나중에 관리자 화면에서 사용할 수 있으므로 원본 데이터 구조는 훼손하지 않는 방향으로 설계해야 합니다.

## 5. 마지막으로 실행한 지시문 요약

사용자는 MSDS 현장 정보제공용 조회 사이트를 만들고 싶다고 요청했습니다.

핵심 방향은 다음과 같습니다.

- 복잡한 관리자용 MSDS 시스템이 아니라 QR코드 접속용 조회 사이트로 만듭니다.
- 작업자가 `이형`, `신너`, `도료`, `S6`, `2차`처럼 일부 단어만 입력해도 관련 제품을 찾을 수 있게 합니다.
- 엑셀 `MSDS_통합대장_누적3.xlsx`의 `통합종합_보기용` 시트를 나중에 검색용 JSON으로 변환하는 방향을 사용합니다.
- 제품 기본정보 1개에 여러 성분정보가 연결되는 구조로 생각합니다.
- PDF는 `/pdf/파일명` 형태로 연결하고 다운로드보다 미리보기를 기본으로 합니다.
- 현재 작업 안내서 기준에 따라 실제 사이트 코드나 실제 데이터 처리는 하지 않고 문서 기획으로만 정리했습니다.

앞으로 작업이 끝날 때마다 이 파일도 함께 업데이트해야 합니다.
